# JARVIS Student Copilot

## Put JARVIS online

Put the contents of this folder at the root of a GitHub repository. Then choose **New → Blueprint** in Render and connect that repository. Render reads `render.yaml` from the repository root and assigns a public `onrender.com` URL. GitHub Pages alone cannot run this Node server, SQLite database, or Ollama bridge; use GitHub for the source and Render for the live demo.

The deployed app cannot use the Ollama model installed on this PC. Set `OPENAI_API_KEY` in Render's secret environment-variable prompt for generated AI responses on the public site; keep it out of source files and chat. Hosted AI use may incur charges from the AI provider. Without the key, judges can still use the browser-only **DEMO · OFFLINE** tutor and the rest of the site; demo answers are clearly marked and are not generated by a language model. The Blueprint sets a shared limit of 120 AI requests per UTC day and 8 per IP per minute as basic abuse protection.

Email/password accounts use the local SQLite database described below. This SQLite database is not yet configured for public hosting: the free Render filesystem is temporary, so accounts and records may disappear on restart or redeploy. A public launch needs a persistent hosted database and production authentication review. The free Render service is public, may sleep after 15 minutes idle, and can take about a minute to wake on the next visit; see [Render's free service limits](https://render.com/docs/free). Render's [Node web-service guide](https://render.com/docs/web-services) explains port and public binding requirements.

## Use local AI

On Windows, install Node.js 22.5 or newer, then double-click **Open JARVIS.bat** to start the local server if needed and open the working site. Do not open `index.html` directly from File Explorer; the dashboard needs the local server for sign-in and AI features.

## Student hub modules

Open **STUDENT HUB** in the dashboard for the hackathon demo of student-facing features: course catalogue and registration, timetable, lesson/material records, attendance tracking, assignments, practice quizzes/exams, exam-form tracking, admit-card and seating records, coding practice, live-class/poll/discussion records, marks/grades, fee/payment records, feedback, circulars, and student-service requests (including grievance, NEFT, and undertaking examples). Add/edit records, import JSON backups or matching CSV files, download a JSON **BACKUP**, and use **RESET DEMO** to restore the presentation data. The central AI Tutor reads uploaded notes; the planner can use student-hub records when you ask JARVIS for help. Workflows are prototype demonstrations and records are fictional; data is saved per account in the local SQLite database, not synced with GU. It does not conduct official registration, online exams, live classes, fee payments, or submissions. No university password is required or stored.

## Learning Commons: teacher posts, tests, and code lab

Choose **CREATE ACCOUNT** and select **TEACHER** to open the teacher-only dashboard. It includes a teaching planner for classes, breaks, tests, exams, and assignment deadlines, plus separate shortcuts for lecture-note PDFs, tests, coding problems, and flashcard decks. A teacher sees only their own posts and planner entries. Student accounts see the shared teacher timetable and all published classroom posts: students can view PDFs, take tests (the server scores answer keys), solve a teacher's examples in the browser coding lab, and study flashcards. In the student **What should I do now? / JARVIS Pick** panel, enter any topic to generate a quiz or interactive flashcards with the local Ollama model. If Ollama is unavailable, JARVIS creates labeled offline study prompts instead. Teachers can review attempts on content they posted. JARVIS displays exam reminders beginning seven days ahead and assignment reminders one day ahead. Students can optionally enable browser notifications; when enabled, reminders fire while the site is open. PDFs are stored as SQLite blobs; classroom posts, schedules, flashcard decks, and attempts are stored in SQLite alongside accounts and Student Hub data.

Teacher role selection is open for the hackathon prototype; it does not verify university employment or connect to GU systems. The code runner is a browser sandbox for short JavaScript exercises, and its prototype score is reported by the browser. Browser notifications require the student to click **ENABLE BROWSER REMINDERS** and allow them. Do not use this as a secure production exam or code-execution service; production needs verified teacher accounts, persistent hosted storage, and isolated server-side code execution.

## Email/password demo accounts and database

JARVIS uses SQLite at `.jarvis-data/jarvis.sqlite` for demo accounts, per-account Student Hub records, classroom posts, PDFs, teacher schedules, flashcards, and submissions. The server hashes passwords with scrypt and stores only the hash and salt; the browser receives an HttpOnly session cookie. Use **CREATE ACCOUNT** once, then **SIGN IN** with that email and password. Existing databases gain the student/teacher role column automatically; schedule and flashcard tables are created automatically. The database folder is excluded from source control and blocked from static web access. Use demo emails and unique passwords; this hackathon prototype is not a production identity service. Render's free filesystem is temporary, so a hosted demo may lose accounts, uploaded files, and records after restart or redeploy. Use provisioned persistent storage or a hosted database before relying on lasting public data.

JARVIS connects to [Ollama](https://ollama.com/download) on this computer. This project checks its local `/api/tags` endpoint for installed models and sends prompts to `/api/chat`. No model request goes to a cloud provider in Local mode. If Ollama and OpenAI are both unavailable, the **DEMO · OFFLINE** provider keeps the presentation interactive using local excerpts and clearly labeled example responses.

1. Install and start Ollama.
2. In a terminal, download a model, for example:

   ```powershell
   ollama pull qwen3.5:0.8b
   ```

3. Start JARVIS from this folder:

   ```powershell
   node server.mjs
   ```

4. Open http://127.0.0.1:8765 and refresh the page. Pick an installed model from the Local model menu. JARVIS has been connected and verified with `qwen3.5:0.8b` on this computer.

Local mode accepts TXT, Markdown, and text-based PDFs. PDF text is extracted in the browser with the bundled Mozilla PDF.js library and sent to the selected model as note text; page markers are preserved so answers can cite pages. Scanned/image-only PDFs need OCR first. JARVIS uses the lightweight local `qwen3.5:0.8b` model by default on this computer. Email/password accounts and student-hub records are stored in the local SQLite database. The website's timetable and priorities remain illustrative sample entries.

The dashboard retains the original black-and-cyan layout and adds animated star drift, cursor-driven 3D card tilt, card sheen, staggered student-record entrances, deadline pulse indicators, and reduced-motion support.

Upload a PDF or notes, then type a question in JARVIS AI Studio or use **ASK JARVIS BY VOICE** / the microphone button to dictate one. JARVIS answers in the chat and speaks the reply. Voice input requires browser microphone permission and uses the browser's speech-recognition service, which may process audio with its provider; the recognized question and extracted notes are sent to the selected AI provider (Local mode uses Ollama on this computer).

## Optional OpenAI provider

Create `.env.local` in this folder:

```text
OPENAI_API_KEY=your_api_key_here
OPENAI_MODEL=gpt-4.1-mini
```

Restart `node server.mjs`, then select OpenAI API in JARVIS. The API key stays on the server. Notes are sent to OpenAI only when you submit an AI request. API use may incur charges based on your account and selected model.
